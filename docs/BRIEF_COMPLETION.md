# تطبیق با readme1.txt و readme2.txt

مرجع نیازمندی‌ها فایل‌های اصلی بریف است. سرمایه و زمان‌بندی اجباری از `challenge_rules.py` و `competition.py` می‌آیند؛ مثال‌های عددی بریف جایگزین ۵ میلیون تومان ثابت نمی‌شوند. مثال ۶٬۲۵۰٬۰۰۰ تومان در بریف، نسبت به ۵ میلیون تومان برابر ۱٬۲۵۰٬۰۰۰ تومان سود است؛ سود ۱٬۵۰۰٬۰۰۰ تومان نوشته‌شده در آن مثال با فرمول سازگار نیست. محاسبهٔ کد از فرمول استفاده می‌کند.

| نیازمندی | پیاده‌سازی / مدرک | وضعیت و محدودیت |
|---|---|---|
| داده و تحلیل و تصمیم خودکار | `engine.py`، `ta_indicators.py`، MCP رسمی | کندل بسته و استراتژی مشخص؛ پژوهش تاریخی به معنی سود واقعی نیست |
| نقش واقعی AI | `llm_gateway.py`، مدل‌های عددی و veto ورودی | رأی نامعتبر ورود را رد می‌کند؛ خروج اجباری منتظر LLM نمی‌ماند |
| خرید، فروش، پیگیری و لغو | `live_trading.py` و `spot_order_journal.py` | مسیر مستقل با mock آزموده شده؛ برای حساب فعلی هنوز فعال و تأیید مالی نشده |
| جلوگیری از سفارش تکراری | شناسهٔ یکتا و ثبت پیش از ارسال، lookup بعد timeout | restart و پاسخ گمشده آزموده شده‌اند |
| کنترل سرمایه و ریسک | سقف سفارش/exposure، allocation، موجودی، fee، stop/take-profit، drawdown پایدار | بودجه برای عبور از حداقل افزایش نمی‌یابد |
| بازارهای مجاز و قابلیت‌های ممنوع | `challenge_rules.py` و denylist ثابت | فعال‌بودن اسپات و precision/minimum هم الزامی‌اند |
| جلوگیری از self-trading | بررسی سفارش‌های باز همان حساب قبل از ارسال | وجود هر سفارش باز، ارسال جدید را رد می‌کند. کنترل حساب‌های مرتبطِ دیگر نیازمند اطلاعات و کنترل صرافی است؛ wash trading یا سود ساختگی پیاده نشده |
| دلیل هر معامله | جدول `decision_audit` در دفتر واقعی | bars و strategy و decision و hashes کد/قواعد؛ لینک شناسه تصمیم به سفارش؛ دادهٔ حساب و کلید در لاگ تصمیم نیست |
| تکرارپذیری و شواهد | پژوهش frozen/replay قبلی + `judge_live_evidence.py` | ابزار جدید آفلاین، فقط‌خواندنی، بدون مدل یا شبکه؛ زنجیرهٔ لاگ را بررسی می‌کند. زنجیره به‌تنهایی جای امضای مستقل یا snapshot سورس نیست |
| تحقق نتیجه به تومان | توقف ورود و خروج الگوریتمی در ۱۰ دقیقهٔ آخر | fill تضمین نیست. پس از cutoff سفارش جدید ممنوع؛ تسویهٔ واقعی طرح فقط با والکس است |
| اندازه‌گیری بازدهی | `judge_live_evidence.py` | fee به تفکیک دارایی، realized PnL، حجم و تعداد fill؛ با ماندهٔ کوین/سفارش مبهم بازدهی نهایی اعلام نمی‌شود |
| backtest و shadow | موتور و پنل فعلی، گزارش‌های پژوهشی موجود | ledger سایه با ledger واقعی یکی نیست |
| سورس یکسان با نسخهٔ اجرا | hash کد در لاگ هر تصمیم | ثبت commit و snapshot سورس هنگام اجرای کاربر هنوز باید انجام شود |
| ویدئوی حدود ۵ دقیقه و گیت‌هاب | `docs/DEMO.md` و راهنماهای پروژه | ویدئو تولید/ارسال و repo منتشر نشده؛ انجام‌شده تلقی نمی‌شوند |

## وضعیت آزمون

۸۰ تست پاس شد. تست‌های جدید شامل اتصال تصمیم به سفارش، هزینهٔ رفت‌وبرگشت و realized TMN، تشخیص تغییر لاگ، و توقف ورود پیش از cutoff بدون فراخوانی مدل است. همهٔ ارسال‌های مالیِ آزمون از broker ساختگی استفاده کرده‌اند؛ هیچ خریدوفروش واقعی توسط دستیار انجام نشده است.

## مانع عملیاتی باز

کلید فعلی در بررسی خواندنی احراز شد، اما جزئیات بستهٔ اعتباری پاسخ موفق نداد و metadata فعلی MCP حداقل مقدار/مبلغ اسپات را ندارد. این دو مورد به‌جای حدس‌زدن یا حذف گارد، همچنان مانع فعال‌سازی‌اند. راه‌اندازی کامل برای حساب فعلی یا سود واقعی هنوز قابل ادعا نیست. قواعد، deadline، denylist و `.env` در این تغییر دست‌نخورده‌اند.

## اجرای آفلاین شواهد

```powershell
rtk proxy .\.venv\Scripts\python.exe judge_live_evidence.py --journal data/live-orders.sqlite3
```

این دستور معامله‌ای انجام نمی‌دهد. برای نحوهٔ اجرای خود نرم‌افزار توسط کاربر، `docs/LIVE_TRADING.md` را ببینید.
