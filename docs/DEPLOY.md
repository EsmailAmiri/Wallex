# استقرار مدار ۲ با Docker

این تحویل، محصول **paper/shadow و پژوهش** است؛ سفارش واقعی، کنترل سفارش باز یا reconciliation حساب واقعی ندارد. در این نوبت، طبق درخواست کاربر Docker image ساخته و container اجرا نشده‌اند؛ فایل Compose اعتبارسنجی شده و برنامه Python در مرورگر آزمایش شده است. سودآوری پایدار و امتیاز داوری تضمین نشده‌اند.

## اجرای استقرار

روی میزبان دارای Docker و Compose، از پوشه پروژه:

```sh
docker compose config --quiet
docker compose build
docker compose up -d
docker compose ps
```

پنل: `http://127.0.0.1:8876`؛ سلامت: `/api/health`. روی VPS از SSH tunnel استفاده کنید؛ مثلاً `ssh -L 8876:127.0.0.1:8876 user@server`. این پنل بدون لایه احراز هویت برای انتشار عمومی اینترنت طراحی نشده است. پورت Compose عمداً فقط روی loopback میزبان منتشر می‌شود؛ اتصال داخلی container روی ۰٫۰٫۰٫۰ است و Host/Origin درخواست‌ها اعتبارسنجی می‌شوند. برای عوض‌کردن پورت از متغیر `MADAR_HTTP_PORT` استفاده کنید.

فایل `.env` موجود را حفظ کنید. برای نصب جدید بدون `.env`، از `deploy.env.example` یک فایل محلی بسازید و کلیدها را روی میزبان وارد کنید. Compose فایل موجود را فقط‌خواندنی mount می‌کند؛ نبود فایل باعث خطا می‌شود و فایل محرمانه وارد build context یا image نمی‌شود. در Linux فایل باید برای UID 10001 قابل خواندن باشد؛ دسترسی را محدود به مالک سرویس نگه دارید. `docker compose config` بدون `--quiet` و `docker inspect` ممکن است تنظیمات محیط اجرا را نشان بدهند؛ خروجی آنها را منتشر نکنید.

## داده و راه‌اندازی دوباره

دفتر SQLite و cache رأی زبانی در volume نام‌دار `madar_data`، زیر `/app/data` نگهداری می‌شوند. `docker compose down` volume را نگه می‌دارد؛ از `down -v` استفاده نکنید مگر عمداً بخواهید دفتر را حذف کنید. برای backup سازگار SQLite ابتدا سرویس را متوقف کنید، از volume نسخه بگیرید، سپس سرویس را شروع کنید. هیچ backup خصوصی را در سورس یا بسته داوری نگذارید.

پس از restart ایجنت همیشه متوقف بازیابی می‌شود و کاربر باید ادامه را صریح انتخاب کند. تاریخ شروع و دو deadline ثابت‌اند و container جدید اعتبار یا مهلت تازه ایجاد نمی‌کند. watchdog مستقل، اجرای سایه را در زودترین مهلت متوقف و دفتر فرضی را با آخرین قیمت مشاهده‌شده به TMN تسویه می‌کند. فقط خود والکس تسویه واقعی حساب را انجام می‌دهد.

## LLM و MCP

کلید LLM مستقل از کلید حساب والکس است. در Compose، router محلی میزبان با `http://host.docker.internal:20128/v1` معرفی می‌شود؛ برنامه فقط با flag صریح Docker به همین نام میزبان HTTP اجازه می‌دهد. درگاه باید از container قابل دسترس باشد؛ router محدود به loopback میزبان ممکن است به proxy محلی و تنظیم firewall نیاز داشته باشد. برای یک router با HTTPS از متغیر `MADAR_LLM_BASE_URL` استفاده کنید. هیچ آدرس remote HTTP دلخواه مجاز نمی‌شود. گزینه مدل نمونه تضمین موجودبودن provider نیست.

MCP به URL دقیق `https://api.wallex.ir/mcp` محدود است؛ هدر X-API-Key فقط برای همین endpoint و بدون redirect ارسال می‌شود. فقط ابزارهای خواندنی allowlistشده اجرا می‌شوند. در پنل دکمه «بررسی اتصال و مسیر خرید/فروش» اتصال خواندنی و چرخه خرید/فروش **فرضی محلی** را بررسی می‌کند. موفقیت balance نه هویت حساب اعتباری، نه KYC و نه مجوز ارسال سفارش را تأیید می‌کند.

## پژوهش و شواهد داور

image اصلی فقط وابستگی‌های موتور پنل را دارد. شبکه عصبی و LangGraph در مسیر پژوهش مستقل‌اند و به‌صورت پنهان به اجرای سایه ترفیع داده نشده‌اند. برای ساخت image پژوهش در آینده:

```sh
docker build --target research -t madar-wallex-research:2.0.0 .
```

داده عمومی منجمد، model artifact مورد اعتماد و گزارش‌ها را جداگانه mount کنید. مرحله پژوهش خودکار هنگام startup اجرا نمی‌شود. برای شرح معماری، نقش مدل‌ها، محدودیت داده و شواهد پنج رأی واقعی، [برنامه امتیازگیری](SCORING_PLAN.md) و [نتایج](SCORING_RESULTS.md) را ببینید. بسته پژوهشی قدیمی، snapshot همان پژوهش است؛ hashهای آن با محصول جدید یکی نیستند. برای replay آن از سورس داخل همان ZIP استفاده کنید.

## ساختار و محدودیت امنیتی

سرویس با UID 10001، root filesystem فقط‌خواندنی، capabilityهای حذف‌شده، no-new-privileges، tmpfs محدود و healthcheck اجرا می‌شود. فقط volume داده writable است. کد و assetها با COPY صریح وارد image می‌شوند؛ `.env`، دفتر محلی، پوشه comments، screenshots و artifactهای شخصی وارد image نیستند. logهای Docker اندازه و تعداد محدود دارند.

با این دستور می‌توانید آزمون‌های Python را پیش از deploy اجرا کنید:

```sh
python -m pip install -r requirements-research.txt
python -m unittest discover -s tests
```

شروع جدید برای ثبت شواهد سایه تنها پیش از `2026-10-23T23:50:00+03:30` مجاز است. انقضای اعتبار همچنان `2026-10-24T20:32:00+03:30` است. مسیر معامله واقعی و آزمون سفارش واقعی در این نسخه **تکمیل نشده‌اند**؛ محدودیت AGENTS.md درباره ابزارهای صرفاً خواندنی حفظ شده است.
