# پژوهش آفلاین LLM + شبکه عصبی

این مرحله با دستور بعدی کاربر برای پیاده‌سازی و آزمایش تاریخی انجام می‌شود. ارسال سفارش واقعی، شروع سایه جدید یا تغییر حساب انجام نمی‌دهد. `engine.py`، پنل، `.env` و قواعد چالش برای این پژوهش تغییر نمی‌کنند.

## اجزای موجود

- [hybrid_research.py](../hybrid_research.py): ویژگی علّی، برچسب خالص پس از هزینه، Logistic و MLP، کالیبراسیون زمانی، گراف ورودی LangGraph، شبیه‌ساز و مخزن رأی مستقل.
- [run_hybrid_research.py](../run_hybrid_research.py): ثبت طرح آزمایش پیش از ارزیابی، انتخاب آستانه روی tuning، ablation، استرس لغزش و بازپخش دقیق LLM.
- [freeze_research_history.py](../freeze_research_history.py): دریافت تاریخچه عمومی قدیمی‌تر با endpoint پژوهشی REST موجود؛ بدون credential، بدون ابزار حساب و بدون تغییر فایل‌های منجمد قبلی.
- [requirements-research.txt](../requirements-research.txt): وابستگی‌های پژوهش، جدا از مسیر اجرای فعلی.
- [تست‌های پژوهش](../tests/test_hybrid_research.py): جلوگیری از نشت آینده، purge، محدودیت سیاست، ورود/خروج فرضی، عدم انتظار خروج برای LLM و کش تغییرناپذیر.

LangGraph فعلی فقط گراف ورودی آفلاین است. persistence عملیاتی، watchdog زنده، تطبیق سفارش و آداپتور اجرای واقعی هنوز جزو قابلیت‌های موجود نیستند. عبور تست‌ها، آمادگی معامله واقعی را اثبات نمی‌کند.

## قرارداد پژوهش

ویژگی در زمان ورود فرضی i فقط از کندل‌های بسته پیش از i ساخته می‌شود؛ fill خرید در open کندل i با لغزش و کارمزد فرضی است. مدل‌ها در طول هر پنجره ثابت‌اند. LLM فقط نامزد عبورکرده از gate عددی را وتو می‌کند و حق تولید خرید مستقل، تغییر اندازه یا کنترل خروج ندارد.

MLP دارای یک لایه ۱۶ نورونی با regularization است؛ Logistic خط مبناست. scaler فقط روی train fit می‌شود. کالیبراسیون Platt روی بازه زمانی بعدی انجام می‌شود و انتخاب آستانه در بازه tuning جداگانه بعد از آن است. داده همه بازارها با مرزهای timestamp مشترک جدا می‌شود. labelهایی که پایان افقشان به مرز بعدی می‌رسد از آموزش/کالیبراسیون حذف می‌شوند.

حداقل ۶۰ نمونه train و ۲۰ نمونه calibration، با حداقل پنج نمونه از هر کلاس، شرط فنی fit است؛ این حداقل‌ها اثبات کفایت آماری نیستند. هم‌پوشانی نمونه‌ها و وابستگی بازارها در گزارش محدودیت‌ها ثبت می‌شود. خطاهای همگرایی در manifest مدل ثبت می‌شوند و نباید پنهان شوند.

نامزدها از قواعد `ta_trend` ساخته می‌شوند، اما scorer بعدی کندل قبلی جای خود را به meta-label معامله خالص می‌دهد. دو افق از پیش محدودشده ۱۶ و ۴۸ کندل (۴ و ۱۲ ساعت) برای بررسی اثر زمان نگهداری در برابر اصطکاک هزینه در نظر گرفته شده‌اند. خروج افق‌دار یک استراتژی پژوهشی جدید است؛ نتیجه آن با نسخه قدیمی موتور یکی نیست. افق، مدل و آستانه پس از مشاهده نتیجه یک پنجره برای همان پنجره تغییر نمی‌کنند.

هر بازار یک آزمایش مستقل با مبنای ثابت ۵ میلیون TMN، یک موقعیت long، تخصیص حداکثر ۲۰٪، stop برابر ۱٫۵٪، target برابر ۳٪ و drawdown برابر ۵٪ است. میانگین بازده بازارها بازده یک پرتفوی قابل اجرا نیست و سود حساب‌های مستقل با هم به‌عنوان سود حساب چالش جمع نمی‌شود.

نرخ هر سمت ۰٫۳۰٪ فقط سناریوی تاریخی مستند قبلی است؛ این اجرا نرخ جاری حساب را استعلام یا تأیید نکرده است. لغزش پایه هر سمت ۰٫۰۵٪ و سناریوی استرس ۰٫۱۵٪ است. هزینه‌ها و پرشدن‌ها فرضی‌اند، نه پرداخت کارمزد یا معامله واقعی. هر پنجره معاملاتی حداکثر ۷۲ ساعت و پایان آن تسویه فرضی به TMN دارد.

داده‌های اولیه حدود ۱۴۰۰ کندل برای هر بازار داشتند و دارای گپ هستند. در مجموعه گسترش‌یافته، ۶۰ روز قدیمی‌تر از همان نقطه شروع اضافه شده و فایل‌های اصلی دست‌نخورده مانده‌اند. گپ پر نمی‌شود، label عبورکننده از آن حذف می‌شود و warm-up شصت‌کندلی پس از گپ دوباره آغاز می‌شود. اگر موقعیت فرضی هنگام گپ باز باشد، خروج در اولین open مشاهده‌شده ثبت می‌شود؛ قیمت کندل مفقود حدس زده نمی‌شود.

هیچ‌یک از این داده‌های تاریخی، آزمون آینده دست‌نخورده برای انتخاب مدل‌های بعدی نیستند. بخش پایانی قبلاً دیده‌شده با نام `previously_seen_legacy_benchmark` ثبت می‌شود. گزارش نسخه قبلی Antigravity و پرچم `promoted=True` آن معیار پذیرش این پژوهش نیست. این pipeline هیچ معامله واقعی را فعال نمی‌کند و خروجی `promoted=False` دارد تا پژوهش تاریخی با مجوز انتشار یا معامله اشتباه نشود.

## مسیرهای تکرار

در PowerShell از ریشه پروژه؛ دستورهای زیر توضیح workflow هستند. `--llm live` فقط به معنای درخواست سرویس مدل زبانی است، نه معامله زنده.

```powershell
rtk proxy .\.venv\Scripts\python.exe -m pip install -r requirements-research.txt
rtk proxy .\.venv\Scripts\python.exe freeze_research_history.py
rtk proxy .\.venv\Scripts\python.exe run_hybrid_research.py --data-dir data/hybrid-history-60d --extended --horizon 16 --output reports/hybrid-v3-h16
rtk proxy .\.venv\Scripts\python.exe run_hybrid_research.py --data-dir data/hybrid-history-60d --extended --horizon 48 --output reports/hybrid-v3-h48
```

مسیر خروجی اجراشده بازنویسی نمی‌شود؛ برای آزمایش مستقل، مسیر جدید انتخاب و همه آزمایش‌ها حفظ شوند. ویژگی‌های عمومی با hash داده و منبع محاسبه در `data/hybrid-feature-cache/` cache می‌شوند. این cache جای تفکیک زمانی یا فایل داده منجمد را نمی‌گیرد.

پس از ثبت طرح عددی، مسیر ارزیابی LLM برای افق ۴۸ به صورت زیر است:

```powershell
rtk proxy .\.venv\Scripts\python.exe run_hybrid_research.py --data-dir data/hybrid-history-60d --extended --horizon 48 --output reports/hybrid-v3-h48 --llm live --max-calls 60
rtk proxy .\.venv\Scripts\python.exe run_hybrid_research.py --data-dir data/hybrid-history-60d --extended --horizon 48 --output reports/hybrid-v3-h48 --llm replay
rtk proxy .\.venv\Scripts\python.exe -m unittest discover -s tests
```

فقط کلید مستقل 9router از تنظیمات محلی مصرف می‌شود؛ هیچ کلید Wallex یا موجودی به مدل فرستاده نمی‌شود. ردیابی خارجی LangSmith برای این runner خاموش است. هویت cache شامل hash متن واقعی prompt، payload، مدل و endpoint بدون انتشار URL یا credential است. timeout و خطا نیز ثبت و منجمد می‌شوند؛ رسیدن به سقف درخواست‌ها ارزیابی را ناقص اعلام می‌کند و نتیجه ساختگی تولید نمی‌شود. اگر رأی دقیق در replay نباشد، خطا رخ می‌دهد و هیچ درخواست تازه‌ای ارسال نمی‌شود.

بازپخش به همان داده، کد، مدل و تنظیم غیرمحرمانه مدل/endpoint نیاز دارد؛ key برای درخواست شبکه استفاده نمی‌شود. manifest شامل hash کد/داده و نسخه کتابخانه‌هاست. artifactهای مدل فقط از فایل محلی مورد اعتماد تولیدشده همین pipeline بارگذاری می‌شوند.

اگر gate عددی هیچ ورود مجازی نداشته باشد، LLM فراخوانی نمی‌شود. نتیجه صفر در این وضعیت «بدون معامله» است، نه موفقیت پیش‌بینی یا سودآوری LLM.

## مرز مرحله بعد

پیش از هر پیشنهاد استفاده از اعتبار واقعی، مزیت خالص باید روی داده آینده تازه و بدون تنظیم روی آزمون بررسی شود؛ سپس آداپتور حساب اعتباری، تأیید مستقل هویت حساب/شرایط طرح، دقت و حداقل سفارش، idempotency، recovery، fill جزئی، reconciliation و توقف مستقل عملیاتی لازم است. اجازه کاربر نیز جداگانه لازم خواهد بود. گذشت مهلت ثابت مسابقه/اعتبار با هیچ restart یا مرحله پژوهشی جبران یا تمدید نمی‌شود.
