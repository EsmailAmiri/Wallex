**قواعد اصلی طرح اجباری‌اند:** صفر تومان آورده، ۵ میلیون تومان اعتبار، شروع ۱۴۰۵/۰۷/۲۹ ساعت ۲۰:۳۲ و پایان قطعی ۱۴۰۵/۰۸/۰۲ ساعت ۲۰:۳۲ تهران؛ کارمزد اعتبار همین طرح صفر. ۳۴۵ بازار ممنوعه در موتور، سرور و MCP مسدودند. جزئیات در [قواعد هکاتون](docs/CHALLENGE_RULES.md) و دستورهای توسعه در `AGENTS.md` است. بازنشانی جلسه مهلت واقعی را تمدید نمی‌کند.

## اجرای سریع در ویندوز

نیازمندی: Python 3.11 یا جدیدتر. حالت REST و نمایشی با استراتژی‌های قدیمی به پکیج نیاز ندارند؛ برای MCP و استراتژی متن‌باز `ta_trend` محیط مجازی و وابستگی‌های `requirements.txt` لازم است. قلم و فایل‌های رابط محلی هستند.

```powershell
cd C:\Users\Esmail\Desktop\hackathon2\Wallex
python server.py
```

سپس آدرس چاپ‌شده سرور را باز کنید؛ در تنظیم فعلی [پنل مدار](http://127.0.0.1:8766) است. می‌توانید `start.ps1` را هم اجرا کنید. پورت در `.env` با `WALLEX_DASHBOARD_PORT` تعیین می‌شود. سرور فقط روی loopback گوش می‌دهد. خروج از سرور با Ctrl+C؛ اجرای مجدد، جلسه ذخیره‌شده را در حالت توقف بازیابی می‌کند.

برای اجرای دوبارکلیکی، `start.bat` را باز کنید؛ سرور اجرا و مرورگر پس از آماده شدن پنل باز می‌شود.

## قابلیت‌ها

اتصال LLM از طریق 9router و مدل چهارم «Ensemble + LLM» اضافه شده است. کلید مستقل را در `LLM_API_KEY` فایل `.env` وارد کنید؛ راه‌اندازی، نقش دقیق مدل، مهلت جمعه ساعت ۲۳:۵۰ و روش ارزیابی در [برنامه LLM مسابقه](docs/LLM_PLAN.md) آمده است. ثبت مدل در فهرست 9router به معنی آزمون موفق پاسخ آن نیست.

گزارش‌های تاریخی استراتژی `ai_regime`، اندیکاتورها و مقایسه AI با نسخه عددی در [پژوهش اولیه](docs/RESEARCH_1405-07-30.md) و [ارزیابی تکمیلی](docs/RESEARCH_1405-08-01.md) ثبت شده‌اند. صفر بودن افت در برخی پنجره‌های بدون معامله، اثبات سودآوری یا تضمین حفظ سرمایه نیست. گزارش‌ها فرضی‌اند و پنل قابلیت paper/shadow دارد؛ سفارش واقعی ارسال نمی‌کند.

پژوهش جدید LLM، شبکه عصبی و مدل درختی، مستقل از موتور پنل، با هدف تخمین بازده خالص و مقایسه منصفانه پیاده شده است. [برنامه امتیازگیری و راهنمای داور](docs/SCORING_PLAN.md) معیارهای تصویر کاربر، مراحل اجرا، محدودیت‌ها و ساخت بسته بازپخش بدون کلید را توضیح می‌دهد. این مرحله مجوز معامله واقعی یا ادعای کسب امتیاز داوری نیست.

[نتیجه مرحله امتیازگیری](docs/SCORING_RESULTS.md) شامل پنج رأی معتبر واقعی LLM، مقایسه با/بدون وتو، ۶۱ تست و بازپخش موفق بسته داوری با شبکه مسدود است. سودآوری پایدار هنوز اثبات نشده است.

- نمودار کندلی با علامت خرید و فروش، نمودار سرمایه و مشاهده مقدار هر نقطه.
- شروع و توقف ایجنت؛ تعویض مدل‌های یادگیری ماشین، مدل ترکیبی LLM و هفت استراتژی معاملاتی (از جمله `ta_trend` و `ai_regime`) از پنل. EMA، ADX، RSI و ATR از کتابخانه متن‌باز [`ta`](https://github.com/bukosabino/ta) محاسبه می‌شوند.
- معامله کاغذی با قیمت‌های ساختگیِ قطعی یا تست سایه با کندل عمومی والکس.
- مدیریت حجم موقعیت، حد ضرر و سود، سقف افت سرمایه، کارمزد و لغزش قیمت.
- بک‌تست با داده ساختگی، داده واقعی والکس و CSV؛ تسویه پایان آزمون به تومان.
- دفتر دلیل تصمیم‌ها، فیلتر فعالیت‌ها، گزارش JSON و ذخیره SQLite.
- رابط واکنش‌گرا، راست‌به‌چپ، فونت محلی وزیرمتن، پشتیبانی از صفحه‌کلید و کاهش حرکت.

## وضعیت اتصال و اجرای واقعی

**این نسخه سفارش واقعی به صرافی ارسال نمی‌کند.** حالت نمایشی آفلاین است. حالت «والکس» کندل عمومی می‌خواند و اجرای فرضی دارد؛ این حالت سود واقعی حساب چالش محسوب نمی‌شود. در حالت `wallex_mcp` داده مستقیماً از `tools/call` در MCP رسمی `https://api.wallex.ir/mcp` دریافت می‌شود. کلید فقط از متغیر محیطی یا فایل `.env` محلی خوانده می‌شود و در پنل، لاگ یا گزارش بازگردانده نمی‌شود.

## اتصال MCP و کلید حساب

فایل `.env` آماده و در `.gitignore` خارج از Git است. فقط در سیستم خودتان مقدار را وارد کنید:

```dotenv
WALLEX_API_KEY=YOUR_DEDICATED_ACCOUNT_KEY
WALLEX_DASHBOARD_PORT=8766
WALLEX_MCP_URL=https://api.wallex.ir/mcp
WALLEX_MCP_TOKEN=
```

در پنل ← تنظیمات و اتصال ← «اتصال و آزمون MCP» را بزنید. ابتدا handshake، کشف ابزارها و دریافت کندل واقعی بررسی می‌شوند؛ اگر کلید موجود باشد، خواندن موجودی نیز امتحان می‌شود. افزودن کلید به فایل نیاز به راه‌اندازی مجدد ندارد؛ دکمه آزمون را دوباره بزنید. موفقیت عمومی بازار به معنای موفقیت احراز هویت حساب نیست و هر کدام جدا نمایش داده می‌شوند.

**اتصال فعال، MCP رسمی والکس است:** [راهنمای رسمی اتصال](https://wallex.ir/landing/mcp/#steps) و endpoint `https://api.wallex.ir/mcp`. لینک‌ها توسط کاربر ارائه و صفحه رسمی بررسی شد. سرور با نام `api.wallex.ir` و نسخه `1.0.0` شناسایی شد و ۵۲ ابزار معرفی کرد. احراز هویت طبق راهنما با هدر `X-API-Key` انجام می‌شود. خواندن کندل و موجودی از خود MCP رسمی آزمایش و تأیید شدند. این، اتصال ابزارهای والکس به ایجنت پروژه است و به معنی خرید سرویس ایجنت یا فعال‌کردن معامله واقعی نیست.

آداپتور نام و ورودی ابزارهای داخلی را به `wallex_basic_candle_history`، `wallex_basic_get_markets`، `wallex_basic_get_account_balances` و `wallex_basic_get_account_fees` نگاشت می‌کند. پاسخ OHLCV همان اعتبارسنجی و تجمیع ۱۵ دقیقه‌ای موتور را طی می‌کند. ابزارهای رسمی تغییر وضعیت، از جمله سفارش، انتقال، تعهدی و تمدید، با وجود حضور در کشف سرور به کلاینت پروژه اجازه اجرا نمی‌گیرند.

فقط چهار ابزار خواندنی رسمی در فهرست مجاز کلاینت قرار دارند. بررسی قواعد هکاتون به صورت محلی و اجباری باقی مانده است. پل stdio قبلی در `wallex_mcp.py` برای استفاده محلی نگهداری شده و با خالی‌گذاشتن عمدی URL قابل انتخاب است؛ در خطای سرور رسمی fallback پنهان به آن انجام نمی‌شود.

برای نصب مجدد:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

فایل `mcp.config.example.json` نمونه اتصال رسمی برای کلاینت‌های MCP خارجی است و فقط placeholder دارد؛ تنظیم سراسری هیچ کلاینتی تغییر نکرده است. کلید REST صرفاً برای URL دقیق رسمی در هدر X-API-Key ارسال می‌شود. برای مقصدهای دیگر فقط توکن مستقل MCP قابل استفاده است؛ redirect غیرفعال است. تغییر URL یا کلید، نشست قبلی را می‌بندد و اتصال تازه می‌سازد.

آداپتور اجرای سفارش حساب چالش، مدیریت سفارش باز و پرشدن جزئی، تطبیق موجودی و تشخیص قطعی نوع حساب اعتباری، هنوز پیاده‌سازی نشده‌اند. بنابراین این نسخه برای دمو، پژوهش و ارزیابی آماده است، اما برای اجرای پول واقعی آماده نیست. فهرست ممنوعه و زمان‌بندی دقیق طرح توسط کاربر ارائه و در کد اعمال شده‌اند. بازارهای پژوهشی پنل نباید در فهرست ممنوعه باشند.

دریافت داده بر اساس [مستندات رسمی Wallex](https://api-docs.wallex.ir/) و مسیر `GET /v1/udf/history` است. قابلیت‌های زنده سرویس از `GET /v1/udf/config` بررسی شد؛ بازه ۱۵ دقیقه در فهرست سرویس وجود دارد. با این حال، در تست عملی پاسخ یک‌دقیقه‌ای مشاهده شد؛ برنامه فاصله واقعی را تشخیص می‌دهد و فقط گروه‌های کامل را به OHLCV پانزده‌دقیقه‌ای تجمیع می‌کند. شکست ارتباط باعث توقف ایجنت و نمایش خطا می‌شود؛ داده ساختگی جایگزین پنهانی داده واقعی نمی‌شود. بدون اینترنت، حالت نمایشی و CSV همچنان کار می‌کنند.

## راهنمای کار

1. «شروع ایجنت» را بزنید. در حالت نمایشی هر سه ثانیه یک کندل ۱۵ دقیقه‌ای پردازش می‌شود؛ این سرعت، بازپخش است و زمان واقعی بازار نیست.
2. روی نمودار، محل معاملات و در بخش مسیر تصمیم، دلیل و اطمینان را ببینید.
3. ایجنت را متوقف کنید، مدل یا الگوریتم را تغییر دهید و تنظیمات را اعمال کنید.
4. در «آزمایش استراتژی» بک‌تست اجرا کنید؛ تنظیمات **ذخیره‌شده** جلسه در آزمون استفاده می‌شوند. برای مقایسه مدل‌ها، گزارش هر آزمون را جدا دریافت کنید.
5. در «فعالیت ایجنت»، گزارش تصمیم‌ها را فیلتر یا کل دفتر رویدادها را دانلود کنید.
6. برای عوض کردن بازار یا منبع داده، ایجنت را متوقف و موقعیت را تسویه کنید؛ سپس تنظیمات را ذخیره کنید. جلسه تازه ساخته می‌شود ولی اعتبار پایه و پایان واقعی طرح تغییر نمی‌کنند. تاریخچه قبلی در گزارش کامل حفظ می‌شود.

در تست سایه، کندل‌های بسته‌شده بررسی می‌شوند. قیمت بازشدن کندل بعد از سیگنال، **فرض اجرای تاریخی** است؛ قیمت قابل معامله در لحظه دریافت کندل نیست. هیچ ادعای اجرای آن قیمت در صرافی وجود ندارد. وقفه بیش از دو کندل باعث توقف می‌شود تا دوره قطع اتصال به شکل معاملات عقب‌افتاده بازپخش نشود.

## آزمون‌ها

```powershell
python -m unittest discover -s tests -v
node --check static/app.js
```

برای اجرای مجموعه کامل شامل آزمون‌های MCP، از `.\.venv\Scripts\python.exe -m unittest discover -s tests -v` استفاده کنید.

آزمون‌ها حسابداری رفت‌وبرگشت، سقف سرمایه، نبود دسترسی به آینده، اجرای کندل بعد، حفظ حد ضرر پس از برگشت قیمت، توقف افت سرمایه، ورودی نامعتبر و تکرارپذیری بک‌تست را بررسی می‌کنند. Node فقط برای بررسی اختیاری جاوااسکریپت است و برای اجرای محصول نیاز نیست.

آزمون مرورگر `tests/browser.cjs` با Playwright اختیاری است. شروع، توقف، تعویض مدل و استراتژی، بک‌تست، ذخیره ریسک، نمایش موبایل و خروجی گزارش را بررسی می‌کند. برای اجرا، بسته `playwright` و یک Chromium نصب‌شده لازم است؛ می‌توان مسیرشان را با `PLAYWRIGHT_MODULE` و `CHROMIUM_PATH` تعیین کرد. اجرای آن جلسه آزمایشی جاری را بازنشانی می‌کند.

## اجرای قابل تکرار بدون رابط

```powershell
python backtest.py --model ensemble --strategy momentum --output reports/demo.json
python backtest.py --source wallex --output reports/wallex.json
python backtest.py --csv static/sample.csv --output reports/csv.json
python backtest.py --replay reports/demo.json --output reports/replayed.json
```

فرمان replay داده و تنظیمات همان گزارش را دوباره اجرا و برابری دقیق شاخص‌ها و معاملات را بررسی می‌کند. گزارش دانلودشده از صفحه بک‌تست نیز ورودی معتبر همین فرمان است.
